# План статьи: Юридическое поле экспериментов для RAG

## Структура

### 1. Зачем вообще юридические документы
- RAG — модная тема, но юридика — это стресс-тест
- Точные типы ответов (boolean, date, name, number) — нет места галлюцинациям
- 300 документов, 900 вопросов, 2 попытки → цена ошибки высока

### 2. Что такое ARLC и как устроена метрика
- Warm-up + Final, структура соревнования
- Формула: `Total = (0.7 * S_det + 0.3 * S_asst) * G * T * F`
- Почему G — это множитель, а не слагаемое → главный инсайт

### 3. Путь от 0.36 до 0.78: хроника недели
- v3: GPT-4, всё в контекст → G=0.451, Total=0.362
- v5: Qwen 3.5-flash 1M CAG, 350K токенов в промпт → G растёт, но не масштабируется
- v7: BM25 + semantic + RRF → G прыгает с 0.56 до 0.72 за один шаг
- v12: dual-model + pinning maps → G=0.896, Total=0.749
- v15: финальная полировка → 0.780

### 4. Три неочевидных находки

#### 4.1 Retrieval важнее генерации
- G — множитель. Если retrieval плох — хороший ответ ничего не спасёт
- Конкретные цифры: G 0.45→0.90 при почти неизменном S_det

#### 4.2 Два режима одной модели
- Reasoning для boolean/name/names, non-reasoning для date/number/free_text
- Разница: 8–16% accuracy на одних и тех же вопросах
- TTFT tradeoff: reasoning медленнее, но F-множитель это учитывает

#### 4.3 Pinning maps: когда правила бьют ML
- Юридические документы структурированы: page 1 закона = все реквизиты
- Детерминированные правила поверх семантического поиска
- Примеры: CASE_PAGE1_MAP, LAW_PAGE1_MAP, REG_SCHEDULE_MAP

### 5. Gold set за $0.21
- Зачем строить свой eval
- verify_v2.py: структурная проверка + Grok plausibility + re-ask from docs
- 900 вопросов, $0.21, 989K токенов
- Ловушка: gold из своих ответов → ~16% ошибок → gap финал (0.631 vs 0.780)

### 6. MORAG — что это и зачем открытый код
- Архитектура: hybrid retrieval, dual-model, pinning maps
- Почему open-source: воспроизводимость, совместная разработка
- Ссылка на репо
